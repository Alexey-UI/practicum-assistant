# Practicum Assistant

TypeScript + Playwright для автоматизации интерфейса курса
<https://practicum.yandex.ru/profile/ap-frontend-st/>. Требуются Node.js 22.18+,
Google Chrome и GitHub CLI (`gh`).

```sh
npm ci
gh repo clone Alexey-UI/practicum-frontend-solutions solutions
npm run login
npm run explore
npm run check
npm test
npm run status
```

`login` открывает отдельный профиль Chrome. Войти нужно вручную, после чего
нажать Enter в терминале. Сессия хранится только в `.local/browser/`.
Одновременно с этим профилем работает только одна команда.
Обычный запуск работает в фоне и не открывает окно поверх других приложений.
Если нужно видеть браузер во время отладки, добавьте `--headed`:
`npm start -- --headed --url 'https://practicum.yandex.ru/learn/.../'`.
Команда `login` всегда открывает видимое окно для ручной авторизации.

Исследовательская команда `explore` принимает JSON в терминале:

```json
{"action":"snapshot"}
{"action":"click","role":"button","name":"Полегчало!"}
{"action":"dom","css":".content-expander"}
{"action":"network"}
{"action":"close"}
```

Снимки интерфейса сохраняются в `artifacts/`, ответы и журнал — в `.local/`.
Эти папки исключены из публикации: в них может быть информация из аккаунта.
Пароли, cookies и токены программа не выводит.

```sh
# Только собрать структуру выбранного модуля, без прохождения уроков:
npm start -- --catalog-only --course 'Вёрстка. Семантика'

# Начать с уроков проектных работ:
npm start -- --projects-first

# Открыть определённый урок для автоматизации:
npm start -- --url 'https://practicum.yandex.ru/learn/.../'

npm run projects -- list
```

Подтверждённые на реальном интерфейсе элементы: кнопки модулей, темы в модальных
окнах, ссылки уроков, статусы `course-navigation-lesson_status_solved`, кнопки
раскрытия `.content-expander__button` и переход «К следующему уроку».
Перед действием программа проматывает доступное содержимое небольшими шагами.
Прокрутка учитывает внутренний контейнер урока и продолжает работу после раскрытия
или догрузки нового фрагмента.

Обработчик вопросов распознаёт радио-кнопки, флажки и обратную связь Практикума.
Неизвестный вопрос сохраняется в `.local/pending-question.json`. Решение можно
указать в `.local/decisions.json` как объект `{ "ключ вопроса": ["текст ответа"] }`.
Ответ попадёт в базу только после положительного результата проверки на странице.
Перебор вариантов ограничен и включается исключительно для явно исследованных
уроков с повторными попытками через `retryableLessons` в `practicum.config.json`.
Селекторы вопросов и обратной связи настраиваются в том же файле.

Тренажёры с Monaco обрабатываются отдельно от теории. Проверенные решения лежат
в `data/trainers/` и привязаны к ID задания, урока и хешу исходного файла.
Программа вставляет код командой редактора, сверяет содержимое и нажимает
штатную кнопку проверки. Между заданиями переходит после подтверждения успеха;
затем отдельно проверяет галочку всего урока. Два урока темы «Семантика и
глобальные атрибуты» (пять заданий) прошли проверку на реальном аккаунте.
Неизвестное задание сохраняется в `.local/pending-task.json`.

Для исследования нового задания подготовьте `.local/task-solutions/<ID>.json`
с полями `taskId`, `lessonId`, `files: [{name, initialHash, content}]`.
Команда `explore` принимает `{"action":"check-candidate"}`: она проверяет решение
на платформе и сохраняет его в библиотеку только после положительного ответа.
При неизвестном результате отправка остаётся ожидающей и не повторяется.
`{"action":"solve-task"}` применяет уже подтверждённое решение.

Для пополнения библиотеки используйте `npm start -- --research --use-catalog`.
Перед этим выполните `npm start -- --catalog-only`. Режим исследования сохраняет
неизвестные задания и ждёт подготовленного решения до 30 минут, проверяя его
через интерфейс. Обычный запуск использует подтверждённую библиотеку и останавливается
на незнакомом задании. Полное покрытие всех модулей пока не подтверждено.

Открытый репозиторий эталонов: <https://github.com/Alexey-UI/practicum-frontend-solutions>.
Первая работа «Оно тебе надо» прошла официальный GitHub Action и принята Практикумом.
«Посмотри в окно» также прошла официальный GitHub Action и принята Практикумом;
её подготовка, проверка, публикация и отправка выполнены основным проходчиком.
Практикум создаёт собственные репозитории сдачи
после привязки GitHub (для первого проекта — `Alexey-UI/ono-tebe-nado-ad`).
Публикация эталона и отправка в Практикум — разные действия.

```sh
npm run projects -- prepare ono-tebe-nado-ad
npm run projects -- verify ono-tebe-nado-ad
npm run projects -- publish ono-tebe-nado-ad
```

Для второй работы используйте идентификатор `posmotri-v-okno-ad`.
Локальная проверка её интерфейса: `npm run check:window`.

Сопоставления через выпадающие списки поддерживаются отдельно от радио-кнопок.
Программа сверяет все строки по маркерам проверки и сохраняет принятые пары в
`data/matching/`. Новое сопоставление попадает в `.local/pending-matching.json`,
решение для режима исследования задаётся в `.local/matching-decisions.json`.
В отчёте `status` учитываются исходный каталог и отдельно подтверждённые галочки;
дата каталога показывает, когда сведения с платформы собирались в последний раз.

`prepare` получает закреплённый SHA из библиотеки и переносит файлы в репозиторий
сдачи, сохраняя Git и оригинальный workflow. При локальных изменениях перенос
останавливается. `verify` проверяет именно перенесённые файлы. `publish` проверяет
их неизменность, делает репозиторий открытым и выполняет обычный push.
При достижении известного урока сдачи основной скрипт выполняет эту цепочку,
дожидается успешного официального теста, отправляет работу через интерфейс
Практикума и отдельно проверяет галочку урока. Состояние отправки сохраняется,
чтобы не повторять её после потери ответа.

Сеть может загружать урок несколько минут. Загрузка страниц повторяется
ограниченно; отправка ответов не повторяется при неизвестном результате.
Неизвестные экраны сохраняются для разбора. Галочка прохождения проверяется
отдельно: смена URL сама по себе её не подтверждает.

Проверенные ответы включены в `data/answers.json`; новые подтверждённые ответы
сначала сохраняются локально. Для публикации обезличенного набора выполните
`npm run answers -- export`. Тексты вопросов и адреса аккаунта в экспорт не входят.

Личные опросы по умолчанию требуют решения пользователя. Чтобы выбирать
однозначно нейтральные варианты, скопируйте `practicum.config.example.json`
в `practicum.config.json` (`feedbackPolicy: "neutral"`). Свободный отзыв программа
не пишет; если нейтрального ответа нет, останавливается для разбора.

Третий проект «Сложно сосредоточиться» (`slozhno-sosredotochitsya-ad`) прошёл
официальный GitHub Action и принят Практикумом. Локальная проверка: `npm run check:focus`.
Проверка охватывает шесть ширин экрана, галерею, клавиатуру, сохранение темы и
шесть сочетаний выбранной темы с системной.

При возобновлении проходчик сверяет галочки в боковом меню и обновляет каталог
по фактически найденным отметкам. Локальный журнал сам по себе не служит
причиной пропустить урок. SIGINT/SIGTERM закрывает браузер и освобождает блокировку.
