# Practicum Assistant

TypeScript + Playwright для автоматизации интерфейса курса
<https://practicum.yandex.ru/profile/ap-frontend-st/>. Требуются Node.js 22.18+,
Google Chrome и GitHub CLI (`gh`). Для нового компьютера используйте Node.js 24.

Установите [Node.js с npm](https://nodejs.org/en/download),
[Git](https://git-scm.com/downloads/), [Chrome](https://www.google.com/chrome/)
и [GitHub CLI](https://cli.github.com/), затем откройте новый терминал.
Нужны собственные аккаунты GitHub и Практикума с доступом к указанному курсу.

| Система | Терминал и особенности |
| --- | --- |
| Windows 11 | Командная строка (`cmd.exe`) или PowerShell. Если PowerShell запрещает `npm.ps1`, используйте `npm.cmd` вместо `npm` в командах ниже. |
| macOS 14+ | Приложение «Терминал»; Chrome поддерживает Intel и Apple Silicon. |
| Linux | Ubuntu 22.04/24.04 или Debian 12/13, x86-64, с установленным Chrome и рабочим столом для первого входа. |

Требования к ОС приведены в [документации Playwright](https://playwright.dev/docs/intro#system-requirements).
На Linux без графической сессии ручной вход через `login` недоступен.

Выполняйте команды по одной строке. Первые четыре проверяют установленные инструменты:

```sh
node --version
npm --version
git --version
gh --version
git clone https://github.com/Alexey-UI/practicum-assistant.git
cd practicum-assistant
npm ci
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git --hostname github.com
npm run setup
npm run login
npm start
npm run status
```

При входе в GitHub выберите свой аккаунт. Команда
[`gh auth setup-git`](https://cli.github.com/manual/gh_auth_setup-git) настраивает Git
на использование авторизации GitHub CLI для последующего push по HTTPS.
При `npm run login` войдите в Практикум в открывшемся отдельном Chrome, дождитесь
программы курса и нажмите Enter в терминале. Пароль и коды вводятся только в браузере.
После этого `npm start` работает в фоне. Входить вручную при каждом запуске не требуется.

Для остановки нажмите Ctrl+C и дождитесь сообщения о сохранении состояния.
Для продолжения выполните `npm start` из той же папки. Не запускайте второй
экземпляр и не удаляйте `.local/run.lock`, пока первый процесс работает.
На медленной сети загрузка может занимать несколько минут.
Незнакомое задание или неизвестный результат проверки приводят к остановке для
разбора. Не очищайте историю проверок, чтобы принудительно повторить отправку.

`npm run status` показывает прогресс основной программы (`solved / lessons`),
принятые проекты (`acceptedProjects`), отложенные опросы (`deferredLessons`),
недоступные уроки (`unavailableLessons`), закрытые уроки (`locked`) и проверки
с неизвестным результатом (`pendingTrainerChecks`, `pendingInlineChecks`).
Сообщение о завершении обхода не означает, что все эти счётчики стали нулевыми.
При остановке сохраните текст ошибки и ссылку на текущий урок. Не передавайте
другим людям `.local/`, профиль Chrome, cookies, токены или полный архив снимков аккаунта.

Автоматически проходят доступные уроки с известными решениями и четыре проекта
с проверкой Практикума. Учительские сдачи остаются черновиками; Mesto с сервером
требует личных параметров подключения. Свободные отзывы не заполняются,
недоступные и закрытые задания не получают искусственных отметок.
Полная проверка всех упражнений ранее прочитанных уроков пока продолжается.

`setup` проверяет Chrome, Git и аккаунт GitHub CLI, получает библиотеку эталонов
и записывает текущий GitHub-логин в локальный `practicum.config.json`.
Проекты публикуются в аккаунт запускающего программу. Перед изменением файлов
или публикацией программа сверяет владельца назначения с аккаунтом `gh`.
Для сдач с автоматической проверкой репозиторий должен быть создан и связан
с Практикумом штатным способом на странице задания.
Ссылки на уроки сдачи уточняются по каталогу текущего аккаунта: номер спринта
из исходного манифеста не используется, если для того же ID урока найден другой адрес.
Скопировать чужой `.local/` для запуска нельзя: там сессия и история другого аккаунта.
Проверка кода: `npm run check` и `npm test`. Исследование интерфейса: `npm run explore`.

`login` открывает отдельный профиль Chrome. Войти нужно вручную, после чего
нажать Enter в терминале. Сессия хранится только в `.local/browser/`.
Одновременно с этим профилем работает только одна команда.
Обычный запуск работает в фоне и не открывает окно поверх других приложений.
Дополнительные модули React и ИИ по умолчанию исключены из обхода.
Уже пройденные уроки и решения сохраняются. В `status` основной прогресс показывают
`solved` и `lessons`, а сохранённый прогресс исключённых модулей — `excludedSolved`.
При необходимости их можно включить настройкой `includeAdditionalModules: true`.
Если нужно видеть браузер во время отладки, добавьте `--headed`:
`npm start -- --headed --url 'https://practicum.yandex.ru/learn/.../'`.
Команда `login` всегда открывает видимое окно для ручной авторизации.

Исследовательская команда `explore` принимает JSON в терминале:

```json
{"action":"snapshot"}
{"action":"click","role":"button","name":"Полегчало!"}
{"action":"dom","css":".content-expander"}
{"action":"network"}
{"action":"close"}
```

Снимки интерфейса сохраняются в `artifacts/`, ответы и журнал — в `.local/`.
Эти папки исключены из публикации: в них может быть информация из аккаунта.
Пароли, cookies и токены программа не выводит.

```sh
# Только собрать структуру выбранного модуля, без прохождения уроков:
npm start -- --catalog-only --course 'Вёрстка. Семантика'

# Начать с уроков проектных работ:
npm start -- --projects-first

# Открыть определённый урок для автоматизации:
npm start -- --url 'https://practicum.yandex.ru/learn/.../'

npm run projects -- list
```

Подтверждённые на реальном интерфейсе элементы: кнопки модулей, темы в модальных
окнах, ссылки уроков, статусы `course-navigation-lesson_status_solved`, кнопки
раскрытия `.content-expander__button` и переход «К следующему уроку».
Перед действием программа проматывает доступное содержимое небольшими шагами.
Прокрутка учитывает внутренний контейнер урока и продолжает работу после раскрытия
или догрузки нового фрагмента.

Обработчик вопросов распознаёт радио-кнопки, флажки и обратную связь Практикума.
Неизвестный вопрос сохраняется в `.local/pending-question.json`. Решение можно
указать в `.local/decisions.json` как объект `{ "ключ вопроса": ["текст ответа"] }`.
Ответ попадёт в базу только после положительного результата проверки на странице.
Перебор вариантов ограничен и включается исключительно для явно исследованных
уроков с повторными попытками через `retryableLessons` в `practicum.config.json`.
Селекторы вопросов и обратной связи настраиваются в том же файле.

Тренажёры с Monaco обрабатываются отдельно от теории. Проверенные решения лежат
в `data/trainers/` и привязаны к ID задания, урока и хешу исходного файла.
Программа вставляет код командой редактора, сверяет содержимое и нажимает
штатную кнопку проверки. Между заданиями переходит после подтверждения успеха;
затем отдельно проверяет галочку всего урока. Актуальное число принятых заданий
показывает `npm run status` в поле `verifiedTrainerTasks`.
Поля `pendingTrainerChecks` и `pendingInlineChecks` отдельно показывают сохранённые
отправки тренажёров и встроенных упражнений без определённого результата:
галочка урока сама по себе не подтверждает приёмку его упражнения.
Неизвестное задание сохраняется в `.local/pending-task.json`.
В локальных данных исследования также сохраняются ссылки из условия и видимые
имена ресурсов проекта, включая шрифты; бинарные файлы не открываются как код.
Шаги, которые требуют только изучить готовый проект, описаны в `data/trainer-demos/`.
Для них сверяются условие, иллюстрации и все исходные файлы; переход «Далее»
допускается только при отсутствии кнопки проверки. В число принятых заданий такие шаги не входят.

Если в условии прямо сказано, что проверок результата не будет, используется
отдельная самопроверка. Упражнения с `verification: "self"` обновляют предпросмотр,
проверяют заданные состояния элементов (`practiceChecks`) и один раз завершают
шаг штатной кнопкой. Проверка `:active` отпускает мышь вне ссылки, чтобы не
переходить на внешний сайт. Такие решения лежат в `data/practice/` и учитываются
в `selfCheckedPracticeTasks`, отдельно от принятых автопроверкой.

Встроенные упражнения Flems с CodeMirror обрабатываются через штатные вкладки,
ввод редактора и кнопку «Проверить». Подтверждённые решения лежат в `data/inline/`.
Примеры с надписью «Проверка не требуется» пропускаются. Новый кандидат задаётся
в `.local/inline-solutions/<ID>.json` по данным `.local/pending-inline.json`;
успех подтверждается зелёным маркером результата, а не галочкой урока.
Результат проверки сохраняется до повторного чтения кода. После сбоя он
восстанавливается только при совпадении условия и всех изменённых файлов;
повторная отправка ожидающей проверки не выполняется.
Для проверки таких упражнений в уже прочитанных уроках используйте
`npm start -- --audit-inline --research --use-catalog`. Флаг `--url` ограничивает
проверку одним уроком; переход к следующему уроку в этом режиме не выполняется.
Полная проверка встроенных упражнений ранее прочитанных уроков ещё не завершена.
Готовые примеры, которые условие просит только прочитать, описываются отдельно
в `data/inline-demos/` с точной привязкой к уроку, тексту и хешам исходников.
Их код не меняется, проверка не отправляется, в число принятых упражнений они не входят.

Для исследования нового задания подготовьте `.local/task-solutions/<ID>.json`
с полями `taskId`, `lessonId`, `files: [{name, initialHash, content}]`.
Если задание требует новый файл в корне проекта, укажите для него `create: true`
и `initialHash` пустой строки. Проходчик создаёт файл через контекстное меню редактора;
существующий файл без локального подтверждения собственного создания не заменяется.
Команда `explore` принимает `{"action":"check-candidate"}`: она проверяет решение
на платформе и сохраняет его в библиотеку только после положительного ответа.
При неизвестном результате отправка остаётся ожидающей и не повторяется.
После явного отклонения можно подготовить исправленный кандидат. Сохраняйте
первоначальный `initialHash` и все ранее изменённые файлы: проходчик разрешает
заменить только исходник или код своей предыдущей отклонённой попытки.
Другие правки в редакторе требуют отдельного разбора.
`{"action":"solve-task"}` применяет уже подтверждённое решение.

Для пополнения библиотеки используйте `npm start -- --research --use-catalog`.
Перед этим выполните `npm start -- --catalog-only`. Режим исследования сохраняет
неизвестные задания и ждёт подготовленного решения до 30 минут, проверяя его
через интерфейс. Обычный запуск использует подтверждённую библиотеку и останавливается
на незнакомом задании. Полное покрытие всех модулей пока не подтверждено.

Открытый репозиторий эталонов: <https://github.com/Alexey-UI/practicum-frontend-solutions>.
Первая работа «Оно тебе надо» прошла официальный GitHub Action и принята Практикумом.
«Посмотри в окно» также прошла официальный GitHub Action и принята Практикумом;
её подготовка, проверка, публикация и отправка выполнены основным проходчиком.
Практикум создаёт собственные репозитории сдачи
после привязки GitHub (для первого проекта — `Alexey-UI/ono-tebe-nado-ad`).
Публикация эталона и отправка в Практикум — разные действия.

```sh
npm run projects -- prepare ono-tebe-nado-ad
npm run projects -- verify ono-tebe-nado-ad
npm run projects -- publish ono-tebe-nado-ad
```

Для второй работы используйте идентификатор `posmotri-v-okno-ad`.
Локальная проверка её интерфейса: `npm run check:window`.

Сопоставления через выпадающие списки поддерживаются отдельно от радио-кнопок.
Программа сверяет все строки по маркерам проверки и сохраняет принятые пары в
`data/matching/`. Новое сопоставление попадает в `.local/pending-matching.json`,
решение для режима исследования задаётся в `.local/matching-decisions.json`.
В отчёте `status` учитываются исходный каталог и отдельно подтверждённые галочки;
дата каталога показывает, когда сведения с платформы собирались в последний раз.

`prepare` получает закреплённый SHA из библиотеки и переносит файлы в репозиторий
сдачи, сохраняя Git и оригинальный workflow. При локальных изменениях перенос
останавливается. `verify` проверяет именно перенесённые файлы. `publish` проверяет
их неизменность, делает репозиторий открытым и выполняет обычный push.
При достижении известного урока сдачи основной скрипт выполняет эту цепочку,
дожидается успешного официального теста, отправляет работу через интерфейс
Практикума и отдельно проверяет галочку урока. Состояние отправки сохраняется,
чтобы не повторять её после потери ответа.

Сеть может загружать урок несколько минут. Загрузка страниц повторяется
ограниченно; отправка ответов не повторяется при неизвестном результате.
После неожиданного закрытия или аварии Chrome проходчик может дважды открыть
браузер заново и возобновить обход из сохранённого состояния. Ожидающие проверки
сначала наблюдаются, повторная отправка автоматически не выполняется.
Штатная остановка и ошибки проверки не вызывают перезапуск браузера.
Если после повторных загрузок интерфейс урока остаётся пустым, адрес и снимки
записываются в `.local/unavailable-lessons.json`, а обход продолжается без галочки.
`--skip-unavailable` позволяет временно пропустить уже зарегистрированные сбои;
обычный запуск повторно проверяет доступность этих уроков.
Неизвестные экраны сохраняются для разбора. Галочка прохождения проверяется
отдельно: смена URL сама по себе её не подтверждает.

Проверенные ответы включены в `data/answers.json`; новые подтверждённые ответы
сначала сохраняются локально. Для публикации обезличенного набора выполните
`npm run answers -- export`. Тексты вопросов и адреса аккаунта в экспорт не входят.

Личные опросы по умолчанию требуют решения пользователя. Чтобы выбирать
однозначно нейтральные варианты, скопируйте `practicum.config.example.json`
в `practicum.config.json` (`feedbackPolicy: "neutral"`). Свободный отзыв программа
не пишет; если нейтрального ответа нет, останавливается для разбора.

Третий проект «Сложно сосредоточиться» (`slozhno-sosredotochitsya-ad`) прошёл
официальный GitHub Action и принят Практикумом. Локальная проверка: `npm run check:focus`.
Проверка охватывает шесть ширин экрана, галерею, клавиатуру, сохранение темы и
шесть сочетаний выбранной темы с системной.

При возобновлении проходчик сверяет галочки в боковом меню и обновляет каталог
по фактически найденным отметкам. Локальный журнал сам по себе не служит
причиной пропустить урок. SIGINT/SIGTERM закрывает браузер и освобождает блокировку.

Текстовые учебные задания (`quiz_type_text`) обрабатываются отдельно от личных
отзывов. Подтверждённые решения лежат в `data/text-questions/` и сверяются с ID
и хешем условия. Для нового задания создаётся `.local/pending-text-question.json`;
решение задаётся в `.local/text-decisions.json` как
`{"ID": {"promptHash": "хеш из pending-файла", "answer": "ответ"}}`.
Положительный результат подтверждает только штатный маркер
`.quiz__content-block_status_success` вместе с `quiz_answered`.

Четвёртый эталон: `zakrivayuschiy-teg-ad`, проверка `npm run check:closing`.
Она запускает локальный HTTP-сервер для внешнего SVG-спрайта и проверяет шесть
ширин, загрузку картинок при прокрутке, лайки и нативное модальное окно без
перезагрузки страницы. Для работ с `pages: true` в манифесте публикация также
настраивает GitHub Pages из `main:/`. Существующая отличающаяся настройка
не перезаписывается автоматически.

На 19 октября 2026 года официальная проверка четвёртого проекта блокируется
несовместимостью в публичных тестах Практикума: [воспроизведение](docs/official-checker-compatibility.md).
Локальная проверка и GitHub Pages проходят. Практикум принял работу, галочка
урока сдачи подтверждена. GitHub Action остаётся неуспешным из-за описанного
сбоя тестов. Для того же эталона проходчик сверяет версии файлов официальных
тестов, исходный workflow и единственную ошибку в журнале. Если подтверждён
именно описанный сбой, он сохраняет неуспешный CI и ссылку на запуск в
`.local/ci-issues/`, затем переходит к независимой проверке Практикума.
Другие ошибки требуют разбора. Для временного откладывания отдельной сдачи доступна команда:
`npm start -- --research --use-catalog --projects-first --skip-project zakrivayuschiy-teg-ad`.
Этот флаг только откладывает выбранную сдачу и не добавляет ей галочку.

To-do (`to-do`) проверяется командой `npm run check:todo`: добавление, копирование,
удаление, редактирование, сохранение после перезагрузки и ошибки хранилища.
Работы с `review: "teacher"` готовятся, проверяются и публикуются в собственный
GitHub, а сдача остаётся черновиком в `.local/hand-ins/`. Документы, формы,
сообщения преподавателям и обращения в поддержку автоматически не отправляются.
Чтение урока с инструкциями сдачи не считается приёмкой такого проекта.

Табличные опросы поддерживают однозначную нейтральную оценку каждой строки. Если
платформа требует свободный отзыв или нейтрального варианта нет, урок сохраняется
в `.local/deferred-lessons.json` незавершённым, а обход продолжается. `status` показывает
количество таких уроков. Тексты отзывов автоматически не заполняются.

Mesto. Валидация форм (`mesto-ad`) использует Vite и проверяется командой
`npm run check:mesto` после `npm run build` в workspace. Метка `review: "self"`
означает самопроверку по заданию курса: код готовится, проверяется и публикуется,
затем прочитывается урок с инструкцией. Самопроверка учитывается отдельно от
официально принятых проектов.

Серверная часть Mesto проверяется командой `npm run check:mesto-api` на имитации
API: ошибки запросов, состояния сохранения, собственные и чужие карточки, лайки,
профиль, аватар и актуальная статистика. Реальное подключение требует личного
токена и идентификатора группы. Токен вводится в приложении, хранится в текущей
вкладке и не встраивается в публичную сборку.

`projects draft <id>` готовит, проверяет и публикует работу с ручной приёмкой,
оставляя сдачу локальным черновиком. Для Vite-проектов `deploy: "gh-pages"`
публикует собранный `dist` штатной командой проекта и проверяет источник Pages.
`removeFiles` перечисляет конкретные устаревшие файлы предыдущего этапа;
программа удаляет только указанные обычные отслеживаемые файлы чистого workspace,
сверяет их отсутствие перед публикацией и сохраняет изменение в Git.

Адрес `/trainer/.../lesson/.../` может содержать теорию. Редактор определяется
по наличию `/task/` в адресе. После перехода проходчик ждёт готового интерфейса,
затем проверяет галочку урока. Новые эталоны тренажёров содержат `instructionsHash`
вместо полного текста условия; при его изменении применение решения останавливается.
Если исходный файл уже совпадает с решением, повторного ввода кода нет.
Иллюстрации условия сохраняются локально в `pending-task.json`; новые эталоны
дополнительно содержат `contextHash` адресов и подписей этих изображений.
Изменение адреса или подписи останавливает применение эталона до повторного разбора.
Исходники видимых HTML, CSS и JavaScript-файлов в дереве редактора открываются
перед чтением: Monaco может ещё не иметь модели для закрытого файла.
При повторяющихся именах программа останавливается, чтобы не выбрать чужой файл.

В радиовопросах платформа иногда допускает несколько альтернатив. Проходчик
проверяет фактически выбранный вариант по классу строки: после проверки сами
поля могут быть отмечены и у других допустимых ответов. Для флажков по-прежнему
требуется полный правильный набор. Уже принятый ответ сохраняется при возобновлении
без повторной отправки.
